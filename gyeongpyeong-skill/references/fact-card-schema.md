# JSON 사실카드 형식

`scripts/validate_metrics.py`가 읽는 형식이다. 최상위는 아래 객체이며(레코드 배열만 넘겨도 받는다), 예시는 `assets/sample-fact-card.json`.

```json
{"card_version": "v0-잠정 2026-11-14", "verified": false,
 "records": [ ... 지표 레코드 ... ],
 "activities": [{"text": "정책활동", "year": 2025, "source": "쪽·표", "hold": []}],
 "external_factors": [{"text": "외부변수", "source": "..."}]}
```

- `card_version`: `v<번호>-<잠정|검증> <작성일>`. **봉인**은 이 JSON을 출력 0절에 그대로 싣고 이후 단계에서 고치지 않는 것이다. 고칠 일이 생기면 번호를 올려 새 카드를 만들고 1단계부터 다시 한다.
- `activities`, `external_factors`: 스크립트는 검사하지 않는다. 2단계 대조에서 활동 문장의 근거로 쓴다.

## 지표 레코드
| 필드 | 입력 계약 항목 | 구분 | 비고 |
|---|---|---|---|
| `institution` | 기관 | 키 | |
| `report_year` | 실적연도 | 키 | 보고서 표제의 연도(「2025년도 경영실적보고서」 → 2025). 발간·평가 연도가 아니다 |
| `baseline_year` | 기준연도 | 키 | 원문·사용자가 밝히지 않았으면 `null` |
| `comparison_year` | 비교연도 | 키 | 위와 같음 |
| `program` | 제도 | 키 | 인쇄된 이름에서 제도 부분. '육아시간'과 '육아시간제'를 합치지 않는다 |
| `population` | 대상범위 | 키 | 전체/남성 등. 원문에 없으면 `null`(‘전체’로 채우지 않는다) |
| `unit` | 단위 | 키 | 명/일/% 등 |
| `baseline` | 원값 | 값 | |
| `actual` | 신값 | 값 | |
| `change_percent` | 원문에 인쇄된 증감률 | 선택 | 재계산값은 넣지 않는다. 있으면 재계산값과 비교(±0.1%p, 반올림 여유 포함 0.11) |
| `status` | 자료상태 | 선택 | `확보`(기본) / `미확보` / `비해당` |
| `label_as_printed` | 원문 표기 | 권장 | 표제·그래프 제목을 글자 그대로. `program`·`population`으로 나눈 것은 작성자 해석이므로 원문은 여기 남긴다 |
| `definition` | 지표 정의 | 선택 | 원문에 정의가 있을 때 |
| `source` | 출처 쪽·표/셀 | 권장 | 예: `"P94 그래프"` |
| `source_url` | 원문 URL | 선택 | |
| `hold` | HOLD 사유코드 목록 | 선택 | `glossary.md`의 코드. 예: `["LABEL_CONFLICT_HOLD"]` |

키 7개가 정규화 키다. 키 필드를 모르면 지어내지 말고 `null`로 둔다. 그 레코드는 HOLD가 되고 중복 집계에서 빠진다.

## 검사 결과 읽는 법
| 구분 | 의미 | 조치 |
|---|---|---|
| `errors` | 숫자 아님, 증감률 불일치, 같은 키에 다른 값, 원값 0인데 증감률 기재 | 고치거나 Mind/원본 확인으로 반환. 종료코드 1 |
| `holds` | 식별키 미확정, `status`=미확보, 값이 비어 있음, 레코드에 적은 `hold` 코드, **같은 값쌍인데 지표명이 다름**(LABEL_CONFLICT_HOLD 후보) | 해당 항목 HOLD, 단계 상한 CONDITIONAL. `source_conflicts`에 옮겨 적는다 |
| `notes` | 같은 키·같은 값의 중복 인용(정상, 1회만 집계), 원값 0(증가율 산출 불가), 비해당 | 조치 불필요. 문안에서 합산·증가율 표기만 주의 |

`errors`가 없으면 종료코드 0이다. 이 검사는 산술·식별키·값쌍만 본다. 원문 사실성과 의미는 사람이 확인한다. 값쌍 일치는 우연일 수도 있으므로 "후보"이며, 실제 충돌인지는 1단계에서 판단한다.
